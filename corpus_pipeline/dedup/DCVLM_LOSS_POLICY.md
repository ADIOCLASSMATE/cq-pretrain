# DCVLM-baseline：去重与图像监督分离

本发行策略只用于固定版本的 `mlfoundations/dcvlm-baseline-200b@251523f5a04d7a852223454182cea63bc9f95063`。其他数据集继续使用原有筛选和去重规则。

保留内容去重，不恢复 DCVLM 原来的重复采样次数，也不按重复次数加权。原来因为 AI 或质量规则排除的可读记录可以恢复用于理解训练，但不计算图像生成 loss。所有候选重新按原来的任务类型、格式、角色和轮次感知文本、有序精确图像身份去重，每组只选一条可用记录。

## 训练读取契约

新发行目录提供 `readers/dcvlm_loss_policy_reader.py`。`iter_batches` 默认只返回本版本选中的训练记录；`include_unselected=True` 返回全部原始 metadata 行及策略标记，仅用于审计。所有原始列、文字、图片位置和顺序保持不变，追加：

| 字段 | 含义 |
|---|---|
| `dcvlm_selected` | 当前发行版是否选择这条记录，包括去重后的选择结果 |
| `dcvlm_training_ready` | 图片和监督绑定是否可用；此字段不代表已通过去重 |
| `dcvlm_image_loss_allowed` | 是否允许该记录的图片成为生成监督目标 |
| `dcvlm_policy_flags` | 原筛除原因、重复、修复和复核历史的位标记，定义见发行 manifest |
| `dcvlm_previous_decision` | 上一发行版的 keep / exclude / quarantine，供追溯 |

训练消费者必须使用 `dcvlm_image_loss_allowed`。为 false 时，图片仍作为视觉输入，原有文本监督保留，但该记录的所有图像生成目标都应关闭，包括 I2T 的 20% null 分支和多图/交错文档中的生成分支。关闭的目标不能继续计入图像 loss 的归一化分母。该标记不要求切断文本 loss 对共享 backbone 或可训练视觉投影的梯度。

这次交付提供数据标记、解码策略和读取接口，不会自动改变已运行的模型训练代码；直接忽略这些字段使用旧训练入口，无法实现本策略。

## 原始图片与修复

原始 TAR、native Parquet 和旧发行版均不可变。修复审计单独保存原图 SHA、TAR 成员和解码验证。多帧图片采用明确的首帧理解策略；原始图片文件不重写，原帧数和首帧校验值保留在证据中。解码器的像素/字节上限和 EXIF 兼容行为以随发行版冻结的实现和修复 manifest 为准。

确认监督占位符与实际图片成员不匹配的记录不进入训练。仍无法可靠读取的记录保留审计信息，不被伪装成已修复。修复不得通过猜测配图或改变有序图像身份来通过校验。

用户在本次对话中复核四张此前年龄未确认的疑似风险图片为成年人。新版本绑定这份用户复核记录，保留原疑似结论的历史；这些记录可按新规则参与理解训练，图像生成 loss 继续关闭。这不是独立年龄认证。

## 迁移到另一挂载路径

一并复制三个目录：

1. 本次新发行目录，包含 flags、readers、修复证据和 manifest。
2. 原始 `dcvlm_baseline_full_20261028_v3/native` 目录。
3. 原始 `mlfoundations/dcvlm-baseline-200b` 数据目录及其 TAR 相对布局。

从 `readers/ROOTS.example.json` 复制一份外置映射文件，只修改映射值为新挂载根目录，保留键中的原逻辑身份。不得修改已发布的索引、flags 或原始内容。reader 在消费时校验 native 和图片内容身份，允许复制后 inode、mtime 和绝对根目录改变。

普通图片可使用 `read_image` 取得原始编码字节。理解训练若涉及本次恢复的特殊图片，应使用随发行版的 `decode_image` 或严格等价的解码策略，不能继续使用原来直接拒绝多帧/异常 EXIF 的解码分支。

最终数量、选中记录数、图像 loss 许可数和未解决问题以本发行版 `manifest.json`、`COMPLETE.json` 和绑定的修复证据为准。原始总行数与去重后的训练行数分开报告。
