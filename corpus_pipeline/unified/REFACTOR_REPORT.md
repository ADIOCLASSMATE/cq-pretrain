# 联合数据管道重构与验证报告

本次已把 DCVLM 全量运行中实际使用的组件整合为 `unified/` 的统一流程，入口为 `python -m corpus_pipeline joint`。正式目标是 DCVLM-balanced-200b＋gen-und 共用一个输入快照、资产库、筛选结果和去重空间。已完成的 DCVLM 全量产物没有改写；本次没有启动新的 CPU/NPU 平台实例或正式两个集合的全量任务。

## 现在如何处理

1. **规范化并保留原监督。** 已声明的适配器读取来源原始记录，保存原文、角色、轮次、图片槽位和文件定位，提前确定单轮／多轮 T2I、I2T、交错、纯文本等任务类别。类型来自实际结构，不根据 source 名字猜测，不调用 API 重新猜已知格式，不构造 T2I50。
2. **有界并发前置处理。** 原始短边至少 128；每张图以原始编码 SHA 标识。来源能明确排除或保护的先按规则处理，其余运行 Community Forensics CF384＋UniFD，警报进入待复核；同时提取真实 SSCD 特征。原图分辨率和来源合同仅给后期 recaption/layout 潜力标签。
3. **联合来源汇总。** DCVLM 与 gen-und 中相同原图的引用共同对账。来源、检测、完整性冲突保留审计记录；相似图之间不传播来源结论。
4. **复核和质量规则。** 历史确认 AI、质量排除和可用审阅按 exact SHA 复用；本轮只把剩余告警送入已有 Qwen 服务池／商用 API。已复核 uncertain 保留并标注，基础设施失败不能当作已完成。明确模糊／占位图按资产排除；坏 caption 按完整源记录 SHA 排除，其他 caption 不受牵连。
5. **联合 SSCD 搜索与精确监督去重。** 两集合共用特征目录，计算新增跨集合图像对，完成当前目录数值资格及覆盖检查。SSCD `.75` 只生成相似候选。实际自动去重需要相同任务、格式、角色／轮次／图序感知的文本身份和有序精确图像身份；不同描述、QA、方向和交错上下文继续保留。
6. **训练语料索引发布。** 产出逐记录 keep/exclude/quarantine、原 metadata 的顺序选择 mask，以及完整原文和图像引用。10 个必需阶段、集合覆盖、产物 SHA 与掩码全部通过，才发布不可变版本并更新 CURRENT。验证快照明确标为 validation，不能升级成 full。

图像资产层与监督记录层分离，是两个集合合并时最重要的约束。一个图像可只算一次检测，却对应多个有效训练样本；这不等于给同一监督无条件增加采样次数。

## 已实现的模块

| 模块 | 责任 |
|---|---|
| `config.py` / `workflow.py` | 固定策略、依赖图、代码／配置冻结、恢复、统计、阶段回执与统一 CLI |
| `ingest.py` | 完整原监督和原图引用的规范化；显式载体／来源合同 |
| `worker.py` / `pool.py` | 租约队列、高吞吐有界批处理、NPU 资格、每卡进程、继承锁防孤儿重复起卡、停止与失败上限 |
| `cache.py` / `history.py` | 原图 SHA＋完整模型身份复用，部分结果补算、移路径字节核验、不可变跨节点缓存与历史查询 |
| `screening.py` / `policy.py` | 历史与当前证据汇总、剩余告警增量队列、质量范围与不确定性处理 |
| `reference.py` | 本次联合目录的全库精确校准参照，绑定数值语义 |
| `fleet.py` | 复用通用 resource_manager：预算、节点集中、抢占恢复、阶段互斥、停止传播和所有实例封存后的收卡屏障 |
| `release.py` | 全阶段和文件完整性验收、validation/full 隔离、不可变版本及训练读取接口 |

`cluster/`、`postprocess/`、`dedup/` 中已经完成亿级运行的核心算法继续作为后端；旧小样本入口没有被冒充全量算法。根 README 已更新，原说明归档，旧运行状态标明历史性质。

## 实际验证结果

### 真实 DCVLM 全链

证据：[REPORT.json](validation/full_real_20261026_v2/REPORT.json)。使用 ai2d、pixmo_cap、mint_pdf、dolly，以及已知 SSCD 相似图对应的两条 datacomp_1b 原记录，共 **10 条原记录、9 次图像引用、8 张独立原图**。

- 实际在本机 CPU 加载检测器和 SSCD，使用原 TAR 中的真实图像；没有使用测试分数。
- 10 条记录通过，训练读取器读回 10 条；每条原监督的完整 SHA 均核对一致。
- 8 个真实向量，28 个无序图片对全部覆盖，输出 1 条相似候选，原图与监督均未因候选相似度删除。
- 10 个阶段均产生完整回执，最终版本明确为 `scope=validation`。
- 小样本整次执行约 **35.94 秒**。不据此推算亿级吞吐；它既不是 AI 识别准确率评估，也不是 balanced/gen-und 实盘验收。
- 该样本没有触发新的 API 告警，不能据此声称本次新调用了商业 API。有告警、排除和 uncertain 的逻辑由下面的真实历史回放与测试覆盖。

早期 v1 已跑完主流程，但验证报告脚本存在相对路径读取错误；已修复，并用当前全部代码从头重跑 v2。v2 是本报告采用的验收依据。

### 历史图像证据复用

证据：[缓存回执](runs/cache_history_canary_20261026/COMPLETE.json)。历史注册绑定 99,930,890 个已完成资产的桶和任务回执，不逐图复制文件。本次取 10 张真实图，迁移图像读取路径后仍逐一校验原编码字节：10/10 命中，原检测分数逐值一致、512 维 SSCD 向量字节一致，新的模型推理调用为 0。第二次全部命中缓存；改成不兼容的 CPU 模型身份则 10/10 拒绝复用。

约 1.38 秒的这个验证集中在同一 SHA 桶，仅证明复用正确性。随机数百图跨大量桶的生产查询吞吐仍需正式基准，不能当作已完成大规模性能认证。

### 历史 AI／质量判断复用

证据：[7 资产回放](../cluster/runs/unified_policy_validation_20261026/history_noalert_validation_v2/validation.json)。2 条保留、4 条确认排除、1 条已完成但 uncertain，与旧逐行结果一致。其中 4 条确认排除即使本次没有 detector alert 也正确沿用；136,060 个范围外历史／质量名单只记录未命中，不导致小样本失败。这个结果复用了真实既有审核，没有新视觉模型推理。

### 自动化测试

证据：[TEST_SUMMARY.json](validation/TEST_SUMMARY.json)。**185 项管道／调度测试及 43 个子测试通过；另有 10 项 Inspire 适配测试在现有 SDK 环境通过。** 重点覆盖跨集合保留不同监督、严格图像身份复用、部分模型补算、错误不入成功缓存、文件篡改、源 SHA、API 增量原行绑定、STOP、抢占、孤儿锁、预算与节点集中、完整发布与原行读取。

项目 Python 环境未安装 Inspire SDK，扩大测试时对应测试曾因缺依赖失败；已在现有 Inspire SDK 解释器独立运行并全部通过，没有为通过测试伪造平台模块。平台生命周期测试使用离线替身，本次没有申请真实实例。

## 正式两个集合运行前的边界

1. **正式数据尚未挂载到当前环境。** 当前实测来自已有 DCVLM；balanced 官方 WebDataset 格式经过契约夹具验证。不能把小池的样本比例、质量或吞吐直接外推到 balanced。
2. **gen-und 的完整格式覆盖尚待实盘适配。** 当前严格适配 BLIP3o Long/Short、LAION-aesthetics 三个 caption TAR 合同。既往审计中还有散图、外置 JSON/Parquet、编辑和多任务数据；不能只接三个源就宣布 21 个源全量完成。preflight 和 normalize 对未知源／载体明确阻断，正式 full 禁止抽样和只挑部分源。
3. **模型部署与 CPU/NPU 挂载是单独的运维边界。** 自动 fleet 管前置检测和 SSCD；复核使用已经部署且通过资格检查的服务池或 API。使用本地复核池时须把其卡数计入 128 总预算，按运维文档串行切换并确认释放。未实现新管道内自动部署／销毁任意模型服务。
4. **正式精度与吞吐需按新配置复验。** 代码、batch、线程改变后，旧 optimized frontpass 资格不能直接复用；新联合 SSCD 目录也必须重新校准。CPU 小样本不授予 NPU 正式资格。
5. **这是当前通用知识预训练筛选。** 不做全量 recaption、layout JSON 生成或全库逐图质量认证；未决标注仍随候选保留。少于两张可用 SSCD 图像的极小输入目前明确阻断校准，不会生成假的全量完成凭据。
