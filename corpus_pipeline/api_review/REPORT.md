# DCVLM 来源规则、检测器与 API 复核实测

本轮验证了流程可运行，也验证了为什么必须保留“仍无法判断”。来源规则与逐图来源匹配能够提供很强的排除／保留依据；多模态 API 能帮助解释检测器误报，但会误读细节、混淆程序合成与生成式 AI，也会把已知 AI 图判断为像真实照片。当前结果不能支持“接近全对”或自动删除全部 API 疑似图的承诺。

代码和运行结果均位于本项目 `corpus_pipeline/` 下。本轮只生成可追溯的候选索引和人工队列，没有修改原始 DCVLM、gen-und 或训练清单。DCVLM 仍保留原始任务类型；AI caption 不因本模块被过滤。

## 实际运行范围

正式裁判为 `qwen3.5-397b-a17b`、`kimi-k3`、`doubao-seed-2-1-pro-260628`，通过用户的 Anthropic 兼容网关调用。另用 `qwen3.8-27b` 完成一次真实图片连通测试，未把它计作第四家独立裁判。

共 51 张图：来自已有 2,396 张 DCVLM 检测器试验的 46 张，以及 5 张外部已知 AI 对照图。

| 分组 | 张数 | 作用 |
|---|---:|---|
| 检测器触发、进入生产复核分支 | 30 | 检查告警是否有可见依据 |
| 受保护来源但检测器触发 | 4 | 反事实审计；生产路由本应优先保护 |
| 各领域检测器低分样本 | 12 | 检查低分分支；并非全部已逐图核实的真实负例 |
| Community Forensics 作者仓库的 DALL·E 2 示例 | 5 | 检查明显或困难生成图，不估计现代生成模型总体召回率 |

第一轮为 51×3=153 条独立盲审，不发送来源、检测分数、caption、真值或本地路径。第二轮选取 24 张，获得 72 个模型复核位置：18 张来源未解决的候选、5 张 AI 对照、1 张来源保护与 API 意见冲突的审计图。第二轮提供匿名意见和明确标注边界的来源材料；五张 AI 对照继续隐藏来源标签。

第一轮使用 5,000 最大输出 tokens、2,400 thinking budget；第二轮使用 6,000 / 2,400。多数图片直接发送原始字节；小图第二轮保留原图，并附完整图像的最近邻放大视图，不裁剪、不增加新细节。格式、尺寸、哈希、转换、模型和提示词版本均留档。实际网关是否严格按请求预算执行，不能仅凭请求参数保证。

## DCVLM 结果

| 分组 | 来源证据支持保留 | API 倾向非 AI 候选 | 仍无法判断 |
|---|---:|---:|---:|
| 30 张检测器疑似图 | 5 | 14 | 11 |
| 12 张低分领域对照 | 4 | 6 | 2 |
| 4 张受保护告警对照 | 4 | 0 | 0 |
| DCVLM 共 46 张 | **13** | **20** | **13** |

“API 倾向非 AI”只是候选，不是已经证实真实。第一轮 30 张告警中有 16 张三家一致倾向非 AI；第二轮的变化、来源匹配和保守裁决共同形成上表，不能把前后数字之差全归因于 API 提升。

最终 13 张人工队列包括 **9 张 CASIA 字符、1 张 MathWriting 笔画、3 张低清／网页图片**。CASIA 原始官方资料支持人类书写和扫描流程，但当前包装缺少 writer/GNT/字符序号，尚未逐图建立原始对应关系。这十张字符／笔画应优先做来源追踪；反复让视觉模型看相同像素，通常不能证明制作历史。其余三张是 A018 低清人像、A025 咖啡杯、A033 消防站。

本轮亲自查看了关键分歧图、全部 AI 对照及上述人工队列，保留了图像观察记录。人工看图也没有被当作凭空产生的来源真值。A025/A033 的 TAR 配套记录与对应 Parquet 行未找到原始 URL 或上游图片 ID，来源追踪目前缺少这一环。

这些是分层选择样本的描述性结果，不能直接外推全库人工比例、AI 污染率、误报率或准确率。

## 来源证据解决了什么

五张 ChartX 均与作者固定版本的图像 **RGBA 像素完全相同**。先通过完整文本／绘图代码／QA 唯一匹配元数据，再从官方 ZIP 获取对应 PNG，复核尺寸、CRC 与像素；上游 PNG 保留 Matplotlib 3.7.1 标记，本地重封装去掉了元数据，故文件哈希不同。

| 本地编号 | 作者图像 |
|---|---|
| A017 | bar_483 |
| A030 | bar_375 |
| A040 | bar_350 |
| A048 | bar_43 |
| A050 | bar_381 |

作者论文说明 GPT-4 提供数据、文本及代码，图像由绘图库执行代码渲染。按本项目口径，这些属于允许的程序绘图，同时标记数据／代码／文本的 AI 参与；不把数据或文案的 AI 属性直接当作图像像素生成标签。[ChartX 制作流程](https://arxiv.org/html/2402.12185#S3.SS3)

这个结论仅覆盖完成精确匹配的五张，尚未逐图覆盖全部 ChartX 包装数据。ChartX 本来是评测集，精确匹配还应进入后续独立的评测污染检查；本轮不把这项检查混入 AI 图像过滤。

CASIA 官方离线流程包括扫描、分割和灰度处理，小尺寸、白底和灰度边缘并不是 AI 证据。当前已补齐来源级事实，但没有据此声称每张包装图片都已验真。[CASIA 官方离线说明](https://nlpr.ia.ac.cn/databases/handwriting/Offline_database.html)

## API 的具体失误

- **A040 程序柱状图：** Qwen 把吨与百分比放在同一轴的错误、以及对柱高的误读，当作 AI 图像证据；豆包也用数据逻辑推断生成过程。Kimi 倾向程序绘图。逐图来源匹配最终确认应保护，模型意见不能覆盖这一证据。
- **A011 普通文字渲染：** 两家第一轮把平整字体叠在皱纸纹理上的合成痕迹指向 AI。普通数字合成与生成式图像合成需要分开。
- **A018 46×46 人像：** 第一轮出现高置信“手指没有关节”等断言；第二轮承认低清无法核查。放大只方便观察已有像素，不能恢复细节。
- **A025 陶瓷杯：** 模型把釉彩图案误读为杯柄，把不规则或方形杯柄作为生成线索。复核能反驳这些依据，但成图本身仍不足以证明来源。
- **A002 外部已知 AI 建筑图：** 第一轮 Qwen、Kimi 倾向非 AI，豆包倾向 AI；逼真的材质和光照不能作为制作过程的证明。

五张 DALL·E 2 对照在第一轮只有一张达到“三家均高置信 AI、每家至少两条线索”的强一致门槛。其余存在分歧或较弱置信度；将拒判空间保留下来会牺牲自动判定覆盖率。它们仍可凭作者来源记录归为 AI 对照，而不依赖视觉投票。五张旧生成器方便样本不足以校准实际训练库的召回率。[作者示例及标签来源](https://github.com/JeongsooP/Community-Forensics/blob/ee5b71d43db0f3779e1edd64ee927b13f2dd6ad4/eval_using_huggingface.ipynb)

这些现象与专门研究中观察到的“把清晰文字、可信版式当作真实性依据”问题相符，但本试验不移用其他基准的数值作为我们的效果。[SynCred-Bench](https://arxiv.org/html/2606.03348v1#S4.SS7)

## 建议的正式管道

1. **图像来源登记优先。** 为图像记录上游版本、原始 ID、制作过程、证据引用和原始／像素哈希。明确 AI 图来源排除；普通程序图保护；真实父图与编辑关系可核实时，AI 编辑保留并标注。对同一图片的多个任务表示复用图像判断，保留各自文本和训练任务类型。
2. **检测器负责召回候选。** 继续使用冻结的 CF384 / UniFD 告警配置。分领域检查误报，并从低分分支随机抽审；只审核高分分支会漏掉检测器从未召回的 AI 图。
3. **API 独立看图后复核证据。** 三个家族先盲审，再检查分歧、具体线索和替代解释；小图提供完整放大视图。自报 high 不是概率，三家同意也不是三份独立制作证据。第二轮已读其他意见，不能算新增三张独立票。
4. **保留三类图像结论与独立运行状态。** 倾向 AI、倾向非 AI、仍无法判断；API 超时／缺字段单独重试。疑似 AI 编辑不能仅凭成图自动套用“真实父图编辑保留”。
5. **人工与来源追踪接住剩余队列。** 优先解决可一次覆盖大量样本的来源映射；无法证明的保持未知。明确 AI 来源可产生排除索引；未经独立验证的视觉候选暂不自动发布为删除清单。
6. **用独立真值验收后再扩大自动决策。** 需要现代生成图、真实照片、程序图、文档和具有父图血缘的编辑样本，并按来源／生成器划分验证集。分别测误删、漏放、拒判比例和各领域覆盖率。不能用本轮调过提示词、补过来源规则的同批样本报告正式精度。

来源匹配、第二轮意见和人工标注应各有版本，能够回滚。当前 `finalize.py` 会重新检查 ChartX 原图和本地图像的哈希及像素，再应用这五张的来源保护，不靠一段模型理由更改训练资格。
