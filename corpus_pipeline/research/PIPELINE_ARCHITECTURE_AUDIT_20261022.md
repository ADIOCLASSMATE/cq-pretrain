# 增量多模态语料管道架构审计

日期：2026-10-22（Asia/Shanghai）。本文件依据当前代码和本地实测报告提出增量架构；不代表已实现 SSCD、批量 recaption、layout 或分布式发布，也没有启动计算资源。模型选型与 MOSS 原文核查由本轮独立调研补充，以下未把工程建议归为 MOSS 的原始做法。

## 结论与执行顺序

用户提出的“尺寸 → AI → 去重 → 分类 → recaption → layout 精选 → 合入历史数据”方向可行，但任务结构配置应提前，去重必须区分图片与监督记录，发布应是有验收的版本提交。当前范围固定为 gen-und 和 DCVLM（未来包括 DCVLM-balance-200B）：提前逐子源阅读数据卡、准备静态配置，不建设任意数据集自动接入器，也不默认让 API 重新识别已知来源。

建议顺序：

1. **加载经过准备的子源 profile，登记实际源快照。** 子源的 schema、图像定位、角色字段、原生任务、来源证据、尺寸策略和标注路由预先编译进 registry；一次发现输入分片并建立可复用 inventory。运行时只做便宜的 schema／版本／逐记录验证，不逐条调用 API 猜类别。新出现的子源或 schema 漂移隔离后补配置。
2. **低成本检查与精确复用。** 只读获取图片头、尺寸、格式、EXIF 方向；应用分任务尺寸规则；读取字节时计算 SHA256，命中历史资产可复用同版本已验证结果。完整解码、像素 hash 在需要处理图片时完成。
3. **图像来源规则 → 检测器 → 按需 API／人工。** 明确生成来源拒绝；有证据的允许来源按规则处理；未知来源的检测器低分也不等于通过。高分、分歧、风险域及低分随机抽审进入复核。保留“仍无法判断”。
4. **SSCD 候选召回与重复关系确认。** 同时检索已发布历史索引和本次新增资产，生成带依据的关系，不立即把所有相关记录删掉。确切重复先归并资产，近似重复按任务决定是否合并或仅限制曝光。
5. **逐记录验证预配置任务与可用视图。** 按 profile 的确定性规则保留原生方向、轮次、图像角色和交错顺序；给子目录输出类别分布，不能要求一个目录只能属于一个类别。混合子源预先配置允许类型及分流条件。
6. **按类型增量补标注及独立验收。** T2I 生成短／中／长描述；I2T caption 可补描述，QA 则校验／补充答案，其他多轮和交错保留依赖。不是所有任务都需要重写原文。
7. **高价值 layout 子集分支。** 先选足够清晰、结构监督有价值的图片，再生成并校验 JSON；只影响 layout 视图，不因未入选 layout 排除其它有效任务。
8. **split 去污染、曝光控制、可读性与统计验收 → 原子发布。** 发布引用、增量标注和 manifest，原数据只读。与历史库冲突复查后提交新版本，失败不污染当前可训练版本。

廉价精确 hash 去重提前，昂贵 SSCD 位于 AI 排除之后、recaption 之前，兼顾算力与可审计性。已知来源拒绝也可以在读图前短路；“先尺寸”不要求对明确拒绝的生成图再进行无意义读取。

## 1. 当前代码已经具备什么，缺什么

| 能力 | 实际状态与边界 |
|---|---|
| 输入适配、来源与任务规则 | `adapters.py`、`policy.py` 已支持部分 DCVLM／gen-und 结构，按角色和顺序分类；纯 URL 不冒充有图片。应在这些已知源能力上补齐静态 profile，而不是再建通用 API 发现层 |
| 不复制图片的引用索引 | 已实现。原文默认保存 hash／长度／定位；图片保存引用，不复制整库 |
| 可恢复、原子单元输出 | `pipeline.py` 已有单元 fingerprint、SQLite WAL、临时文件替换、校验和、完成标记；一个输出目录只有一个写进程 |
| 分片 worker | 已有 `--worker-index/--worker-count`，但每个 worker 重复发现输入，输出独立；尚无统一任务队列和多 worker 事务合并 |
| 文件内续跑 | 尚缺。Parquet／TAR 当前以输入文件为提交单元，超大单文件失败会整文件重跑；散图按 1,024 条成单元 |
| 像素检测与 API | 已有独立抽样验证模块，未成为核心流水线的正式生产判决阶段 |
| 图像质量与大小 | 核心第一阶段原本是存在性和引用检查，未全量执行解码和尺寸筛选 |
| 历史＋新增图片去重 | 仅保留已有图像 SHA256 候选键；尚未执行全局精确去重或 SSCD |
| recaption／layout | 目前是设计文档，无批量生成器、独立质检和生产模型部署 |
| 发布与训练读取 | 当前 export 只是候选引用导出，`view_materialized=false`；未具备所有新增标注视图的完整训练读取、去污染和事务发布 |

现有 `eligible_for_training=true` 只代表第一阶段规则通过，不能被新执行器直接解释成“已通过 AI、去重、caption 验收并可正式发布”。应保留 stage-1 状态，新增 `release_eligibility` 和逐阶段状态。

## 2. 图片、监督记录与训练视图分别去重

至少维护三类身份：

- **资产 `asset_id`：** 一张具体图像或一个明确派生版本。保留原始字节 hash、可选规范像素 hash、定位和来源血缘。不同尺寸、裁切、编辑不能仅靠相似度变成相同资产。
- **记录 `sample_id`：** 原始 pair、QA、完整对话或交错文档，绑定顺序、角色、文本与资产。不要用图片 hash 代替 sample_id。
- **视图 `view_id`：** 某条记录用于某个任务时的输入／目标、标注选择、loss mask、变换和采样规则。短／中／长 caption 是同资产的可选标注视图，不是三张新图片。

| 重复情况 | 应有动作 |
|---|---|
| 同图同 caption、同任务同方向、相同上下文 | 可合并监督实例，保留所有来源引用与统计 |
| 同图有不同有效 caption 或问答 | 共用资产，保留有新增监督价值的记录；控制资产级曝光 |
| 同图分别用于 I2T 与获准的 T2I | 不因图片相同删除其中一种任务；本项目仍遵守 DCVLM 不反转，T2I 训练来自 gen-und |
| 同图出现在多轮或交错文档 | 复用图像判断和 embeddings，不拆散上下文。删除整条会损失文本与指代关系；删单张会破坏结构 |
| 近重裁切、带字版、编辑前后图 | 保留变换／血缘／近重关系；确认不同版本的任务价值，不自动共享 caption、框或来源结论 |
| 模板相同但数字／文字不同的图表、文档 | SSCD 可能相似，文字和数值却是关键监督；增加 OCR／文本差异核验，禁止仅凭 SSCD 分数合并 |
| 历史低清图与新高清版本 | 可新增更好的资产代表，但原有 QA、OCR 框、裁块坐标不能无校验改绑；否则标注会错位 |

SSCD 适合作为复制候选信号，不是“语义相似即可删除”。阈值须在照片、图表、文档、程序图、裁切及编辑图上分别检查误合并／漏检。近邻图的传递闭包可能将 A≈B、B≈C 但 A≉C 的样本串成一簇；簇内代表和替换应有二次约束。ANN 的检索召回也要用小规模精确搜索校验，不只测阈值。

评测集隔离单独处理：训练历史索引之外还需要评测保留索引。评测命中优先隔离，不能把“历史训练库没有重复”误当无评测污染。同一确定资产及需隔离的近重组不能跨 split 泄漏；带有保留样本的关联文档需要记录受影响范围。

## 3. 尺寸与类型不能互相脱节

图片头检查应早做，但全局统一短边阈值会系统性删掉手写字符、数学笔画、OCR 小块和一些图标。当前实测的 CASIA／MathWriting 疑难图恰好说明了这一点。已知子源 profile 在读图前即可选好尺寸策略，无需先用视觉 API 分类。

建议配置三层：不可解码／零尺寸等全局无效门槛；按任务与域设的最小有效信息门槛；高质量 T2I／layout 的较严格候选门槛。未知域先进入尺寸待判队列，不因暂未分类而直接套用摄影阈值。480 短边目前仅是 layout 设计建议，不是已批准的全库尺寸门槛，也不是 MOSS 的通用标准。

记录原始方向与 EXIF 修正后的宽高、像素面积、长宽比、已知上采样历史；筛选不先放大补足门槛。长条 OCR／文档还要考虑训练分辨率下文字是否可读。对交错文档，一张小图不应自动导致其余整篇内容永久删除；可以隔离受影响窗口，但只有上下文依赖检查通过的派生窗口才能发布。

任务类型推荐分开表达：

```json
{
  "native_category": "multi_i2t",
  "semantic_task": "visual_qa",
  "completed_rounds": 3,
  "input_modalities": ["image", "text"],
  "target_modalities": ["text"],
  "structure_evidence": {"adapter": "messages_v1", "roles_verified": true},
  "allowed_training_views": ["multi_i2t"]
}
```

`single_i2t` 不等于 caption：OCR、计数、选择题、数学推理都是单轮 I2T。混合生成／理解的对话应保留 `mixed_multimodal`，每轮另记 condition/target，不能硬塞进单一 T2I/I2T 类。纯文本可区分普通续写和文本对话，直接绕过图像阶段。

## 4. recaption 要保持任务价值

| 原始任务 | 推荐增强与验收 |
|---|---|
| gen-und T2I caption | 从图像建立可核验事实，生成短／中／长三种描述，覆盖主体、关系、属性、真实可见文字和构图；三者事实一致，长度不是质量代理 |
| I2T caption | 保留原描述和新增描述的来源；按图像核验细节，可选更好的描述视图，仍是图像到文本 |
| 单轮 I2T QA | 保留问题、选项和回答语义；校验图像依据、答案正确性和可回答性；不能把答案直接替换成通用长 caption |
| 多轮 I2T | 全局查看上下文，保留追问和指代，逐轮验证；新增重述是派生标注，不冒充原始对话 |
| 多轮 T2I／编辑序列 | 必须已有真实多轮目标图及其对应关系；给每轮图片与变化补描述，不凭一张图片虚构多轮目标图 |
| 交错序列 | 保留文档顺序、正文、图文局部对应与上下文；可将新图片描述作为 sidecar 增强，不能把整篇改写成独立 caption 列表 |
| 纯文本 | 做文本质量、重复和语言检查；没有图片时不走视觉 recaption |

建议一个强视觉模型生成“图像证据＋候选标注”，不同家族模型重点验证事实、文字、数量、空间关系和问答一致性。若同时用 Qwen 和 Gemma，二者不必对所有图片重复生成三份同构长文；验证失败／高价值场景再双生成比较。原生可靠 OCR／对象框／人工答案优先复用，提供给模型时标成待核验材料，不能代替看图。

短／中／长建议由共享事实约束生成，再逐份核验；长描述尤其容易添加看不见的材质、情绪、地点或背景故事。固定版本的视觉判据、已知答案校验、OCR 比对和人工盲审应共同验收，不能只让生成模型给自己打分。

采样时对同一资产抽取一种 caption 长度，或显式设置资产级总曝光权重。把三条 caption 直接展开成三条全权重数据，会无意将 T2I 该来源采样权重扩大三倍。报告分别统计唯一图像、记录、标注与视图，不相加冒充独立图片量。

## 5. API 与 layout 的高价值位置

付费超大模型适合：无法由来源解释的 AI 告警、少数无法由预配置规则判定的语义样例、局部标注争议、复杂图文关系、layout 高价值边界样本，以及独立分层质检。已知子源类别、schema 和运行计划来自提前准备的配置，运行时不花 API 费用重复猜测。常规生成和确定性校验由本地部署承担。记录模型版本／请求配置／prompt／输入证据，方便以后替换模型而不重跑整个库。

AI 复核应吸收现有实测事实：51 张 pilot 的五张已知 AI 对照仅一张达到三家均高置信 AI，不能把多个大模型一致当成制作历史真值；低分检测分支必须有随机抽审。付费模型识别来源的理由、视觉判断和最终规则判决分列保存。

Layout 选择应同时满足技术质量、结构监督价值和生成标注可验证性。主页展示图可帮助定义目标风格与评分样例，但若其本身为生成结果，就不是允许训练图片的来源证据，更不能直接当作真实图质量标签或无偏评测集。Few-shot 应配“为什么适合／不适合”的量表和跨域边界例，避免只学成海报偏好。正式 layout 框、文字和层级始终由当前输入图约束。

## 6. 高并发与事务边界

建议每个源快照只构建一次不可变 inventory，按 TAR／Parquet 行组／散图块划分 work unit；每个单元明确绑定固定 profile ID／版本，图像在所在存储分区处理。读取、CPU 解码与检测、SSCD embedding、本地 VLM、付费 API、发布分别用有界队列，不为全库预建数亿个内存任务。

每个阶段的缓存键至少包含：输入资产或记录内容身份、处理阶段版本、模型／权重／prompt／解码参数、预处理规则及输出 schema 版本。对话增强还须包含完整上下文 hash，不能只按同一图像复用答案。

- **执行语义：** 允许任务至少执行一次；输出按幂等键至多提交一次。完成回执和输出 hash 一致后才进入下游。用 lease／heartbeat／attempt 防止 worker 掉线永久占有任务。
- **容量控制：** CPU 解码限制同时驻留像素数；NPU 服务按视觉 tokens、上下文和预估输出 tokens 动态批处理；付费 API 按端点并发／请求速率／tokens 配额控制。观察 P95 延迟、429、OOM、超时后自适应降低并发，禁止无限重试。
- **流水线背压：** 下游 caption 排队上升时暂停上游昂贵解码和 embedding；使用持久任务状态及有界中间缓存，不把大量展开图片存内存或落盘等待。
- **错误分流：** 解析失败、图损坏、API 缺字段、未支持来源、来源未知和业务过滤分别计数。未执行不是通过；超时不是“判断不了”的图像结论。
- **跨分区：** inventory 记录 storage_domain 与 resolver。CPU／Ascend 不共通时只共享代码、索引、标注与必要配置，任务调度到能读原图的位置；历史模型产物按资产身份交换。训练发布前必须实测挂载可读。

去重索引必须处理并发竞态：两个作业同时对历史快照查询“无重复”，随后互相重复入库。因此每次运行固定读取 `dedup_base_snapshot_id`，产生暂存 embedding／关系；发布协调器先合并本批内部关系，再检查自基线之后的历史增量，确定代表并原子提交。可采用单发布者或带 compare-and-swap 的索引版本事务。ANN 更新也必须与发布 manifest 一致，不能让部分索引更新可见而对应资产还未发布。

发布建议使用 staging → validate → commit 三步，事务中写入发布记录及 index-update outbox。后台可重试消费 outbox 构建 ANN 分片，索引版本就绪后再切换统一 current 指针；读者固定使用完整快照。共享 SQLite WAL 不应直接跨多节点网络盘当作全局任务队列；先用单协调器管理小规模试点，规模扩大后替换为有明确事务保证的服务，不改变业务表契约。

## 7. 建议的最小持久表契约

| 表／分片 | 最小字段与用途 |
|---|---|
| prepared_profiles | collection/source/subset/version 匹配；数据卡证据；adapter、schema contract、image resolver；允许的原生类型与逐记录判别规则；尺寸／来源／标注路由；配置 revision；未准备来源的隔离策略 |
| sources / inventory | source_id、revision、storage_domain、locator、fingerprint、schema、work_unit_id、发现范围 |
| assets | asset_id、source_asset_refs、bytes_sha256、pixel_sha256、width/height、orientation、decode_status、provenance_evidence_ids、edit_parent_id |
| samples | sample_id、native_category、semantic_task、ordered_segments_ref、asset_ids、roles/turns、original_text_ref、split |
| decisions | entity_type/id、stage、verdict、reason_codes、evidence_ids、rules_version、status、attempt、run_id |
| duplicates | asset_a/b、relation_type、embedding_model_revision、score、threshold_version、verification、cluster_id、base_snapshot_id |
| annotations | annotation_id、entity_id、type、language、length_band、payload_ref、model/prompt/input_hash、AI_text=true、quality_result |
| views | view_id、sample_id、asset_ids、annotation_ids、condition/target、loss_mask、transform、exposure_group、weight、eligibility |
| releases | release_id、parent_release、source_revisions、model/rule_versions、shards＋checksums、dedup_snapshot、coverage、counts、acceptance_report |

图片 bytes 不进入这些表；原始样本／图片的定位仍由 source revision 和 resolver 唯一解析。近重 cluster 不替代 asset_id。已有可靠标注不复制，使用引用；新增标注及规则变化使用增量分片。

profile 覆盖报告应列出 gen-und／当前 DCVLM／未来 balance-200B 中“已配置、已用真实样本验证、仅依据数据卡准备、版本不匹配、尚未覆盖”的子源。名称匹配不等于 schema 验证成功；未来挂载 balance-200B 后复核实际打包差异，不能因为其属于 DCVLM 就自动继承全部通过状态。新来源以后通过添加配置和必要适配器接入，人工审核的是新规则与证据，不是让每次批处理停下来逐项确认。

## 8. DCVLM 先导与验收标准

建议在已有来源和像素审核的 DCVLM 子集上先做贯穿试点，再扩到更大版本。DCVLM 没有足够的原生 T2I／多轮 T2I 时，应明确该分支未验收，待 gen-und 正式挂载后补真实测试，不能反转 DCVLM 制造成功案例。

先导包含照片、图表、文档、渲染／字符、已知编辑血缘、多轮和交错；抽取近重、模板差异、原生不同 QA、低分 AI 审计等挑战样本。小规模样例数量由当前各类覆盖实际决定，不以子源前几条样本外推全量比例。

上线门槛至少检查：

1. 输入文件内容不变；资产／记录／标注／视图计数能够逐层核对；未知和未完成分支不被发布。
2. 逐域尺寸保留率与边界样例人工确认；字符／OCR 受保护任务不会被摄影阈值误删。
3. AI 真值集独立于调提示词的数据，包含现代生成图、真实图、程序图和真实源编辑图；分别报告误删、漏放、拒判与 API 失败，不用总体准确率掩盖域差异。
4. 精确重复可恢复全部来源；SSCD 对模板／文本变化不过度合并；历史、新增、本批重复和双作业竞态均验证，ANN 检索召回有抽样精确基准。
5. 各任务 condition/target／多轮顺序／交错引用保真；保留的 QA 不被通用 caption 覆盖，T2I 三长度事实一致且曝光不被放大。
6. caption/layout 有独立事实检查与人工盲审；版式 JSON 合法与标注准确分别统计。
7. 杀 worker、重复投递、超时、OOM、服务重启和中途断盘后可续跑，无重复提交、无假完成、无部分发布。
8. 在实际训练分区抽取新发布引用，完整恢复图片和目标标注；测读取吞吐、图像解码／模型 tokens 吞吐、P95 延迟、失败率和临时存储峰值。通过后再确定正式并发和服务副本数。

当前最先应补的工程点是共享 inventory＋资产读取/尺寸结果＋独立阶段状态，再把已有 AI 复核做成可恢复阶段，随后接 SSCD 和类型化标注。先保住记录语义和发布事务，再扩并发，能够避免规模增加后难以追回的误删与错配。
