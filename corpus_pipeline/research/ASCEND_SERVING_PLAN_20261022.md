## 结论

推荐的主力组合是 **Qwen3.5-397B-A17B + Gemma 4 31B**：前者承担复杂图文理解、原任务保持和描述生成，后者提供另一模型家族的独立检查与候选描述。这里的 Qwen 升级属于本项目选择；MOSS 当前使用指南提及的 Qwen3.5-27B/35B-A3B 和 Gemma4 不等于要求每个样本必须串行运行所有模型。模型质量仍要以本项目分域盲评决定。

Qwen 的落地条件比预期好：用户已有停止状态的 397B BF16 在线服务、完整可见的公共权重索引，以及历史真实多图视觉验证结果。Gemma 4 31B 官方已经给出 Ascend 路线，但当前空间未找到该权重，视觉推理还需要在实际容器中验证。不能将“框架支持模型名”写成“本项目已可生产使用”。

## 卡数与显存预算

以下是准备验证的起点，不是吞吐承诺。权重分摊之外还需要视觉编码激活、KV cache、通信区、图编译工作区和峰值余量。

| 模型 | 建议首轮配置 | 显存含义 |
|---|---|---|
| Qwen3.5-397B BF16 | 32 × 64GB；优先沿用用户历史 TP8 / DP4 / EP32 验证结构 | 约 751.4 GiB 张量；理想均分约 23.5 GiB/卡，不代表实际每卡相等。官方 A2 BF16 路线同样给出 32 卡 |
| Qwen3.5-397B W8A8 | 16 × 64GB 作为后续吞吐对比 | 约 391.8 GiB 张量；理想约 24.5 GiB/卡。需要对 OCR、细粒度属性和 JSON 输出做 BF16 对照，不能只看文本基准 |
| Gemma4-31B BF16 | TP4：4 × 64GB，之后比较 TP2 和多副本 | 粗算权重约 60–64 GB；TP4 留足视觉/KV 余量。TP2 是否更高吞吐必须测，不因放得下就认定更优 |

397B 官方 A2 指南给出的 BF16 32 卡、W8A8 16 卡可作部署依据；这些不是本次 benchmark。[Qwen3.5-397B Ascend 指南](https://docs.vllm.ai/projects/ascend/en/v0.18.0/tutorials/models/Qwen3.5-397B-A17B.html)

建议先验证一个 Qwen 副本加一个 Gemma 副本，再按队列积压扩副本。不要一开始给所有 recaption 请求保留 128K/256K 上下文；按单图、多图和长交错任务分服务池。初始候选单图 8K–16K、长序列 32K，实际按输入视觉 token 与输出长度分布调整，不能截断任务关键上下文。

## 高并发接入方式

1. 数据 worker 按 shard 顺序读，CPU 解包、尺寸/损坏检查、确切哈希与格式解析先行。独立图像只做一次视觉特征/描述工作，样本保留各自问题、轮次和图文顺序。
2. NPU 服务只接收推理工作；流水线的索引、去重提交、输出封包由 worker / Job 完成。Serving 适合被多个长期数据任务共享；固定数据集的一次性离线推理也可用 Job，不必把整个处理流程放入 Serving。
3. 异步客户端采用有界队列、按模型和任务限流、超时重试、429/5xx 退避；用图像数、视觉 token、输入/输出 token 预算控制负载。提高并发数直到吞吐饱和，随后扩副本，而非无限提高请求并发。
4. 单图/多图/长序列分桶；多轮与交错任务不能照抄官方单图示例的 `image=1` 限制。processor 的 resize / tiling 与源图尺寸分开记录；源图不因 API 预处理而改变。
5. 缓存键包含图片内容、完整上下文、原任务类型、prompt/version、模型权重及 processor 版本、采样配置。只按图像 SHA 缓存最终多轮答案会误用上下文。
6. Qwen 主生成、Gemma 独立核查，局部分歧触发付费 API；不是所有图片都跑全体模型。共享图像可缓存事实清单，但不能把看不到的先验扩写进 caption。
7. T2I 长、中、短版本可在一个结构化请求中生成，分别质量检查、标注合成来源，并作为同图变体管理。I2T/Q&A 保持问题与答案监督；交错文档保留链接及顺序，不能统一改写成图片 caption。
8. 指标同时报成功样本/秒、输入/输出 token 吞吐、P50/P95 延迟、重试/OOM、JSON 合法率、事实错误率、不同域拒绝率。仅靠 tokens/s 不能证明有效数据吞吐提升。

## 进入正式数据前的验证门槛

- 在现有 DCVLM 上建立分域盲评集，含照片、文档、图表、渲染、OCR、编辑、多图和交错上下文，冻结原始标签及人工参考；将未经证实来源保留为 unknown。
- 用同一批样本比较原文、Qwen 输出、Gemma 输出及选出的合并结果，评价可见事实、OCR 准确度、任务保持、关系/数量幻觉、语言自然度；不能让生成器独自给自己的结果打满分。
- BF16 质量基线通过后再比较 W8A8；每次换模型、量化、processor 或 prompt 都产生新产物版本。
- 必须实际验证真实两图输入、复杂分辨率、流式/非流式、JSON schema、长序列和断点恢复。历史服务健康或模型在支持表中打勾不能替代这些检查。
- gen-und 与 DCVLM-balance-200B 挂载就绪后，复用同一 worker/队列/manifest 协议，先小批影子运行并核对统计守恒，再扩容。平台挂载和 CPU/Ascend 存储隔离是独立于模型质量的前提。

本报告提出的 Gemma4 服务及新管道连接尚未部署。本次已有的确定性成果是：平台能力核验、可复用 397B 资产定位、权重索引检查及版本兼容边界说明。
